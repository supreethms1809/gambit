# Gate G0

G0 decides whether a baseline may enter a comparison. It is an entry check. Published-number reproductions are reported in the appendix and run in parallel with the pilot and selection. They do not hold up the pilot, the selection runs, or the writing. The one exception is CVE, below.

User decision, 2026-10-07. The earlier rule required every Core reproduction (B3) before any pilot comparison. That held the contrastive pilot behind shift-baseline reproductions, such as the SpRAy horse analysis, that do not bear on it.

## Entry rule

A Core baseline enters a comparison when it has all of the following:

- the authors' code, pinned (vendored at a commit or a pinned library version), or a reimplementation whose dossier entry names the algorithm it follows;
- passing toy tests and edge cases (B6), and the cross-implementation check (B4) where a reference library exists;
- a merged, reviewed pull request;
- a dossier entry in `docs/paper/BASELINES.md`.

## Reproduction rule

Each reproduction in B3 is run and reported in the appendix table, with its tolerance and result. A reproduction that misses its tolerance is debugged before the freeze. If it still misses at the freeze, the appendix states the gap and the main table marks that baseline's row.

CVE is our reimplementation, and no official code exists. Its CUB edit-count reproduction must be recorded before the freeze for CVE to stay in family C. If it is not recorded by the freeze, family C is CDEA vs margin attribution and CDEA vs contrastive Extremal Perturbations, Holm over 2, and CVE is reported as an exploratory row. This rule is fixed before any pilot number is read.
