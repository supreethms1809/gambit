# CDEA paper plan: experiments, evaluation, and writing, run against the lessons guide

## Context

Target: an ML/CV conference paper (NeurIPS/ICLR/CVPR class). The contrastive game and the
shift-aware game are co-equal contributions. There is no user study; usefulness to people is
listed as a limitation.

The lessons guide (`~/Downloads/PAPER_LESSONS_AND_WRITING_GUIDE.md`) comes from a paper that
needed a major revision. The audit of this repo shows that it is already repeating most of
those mistakes. The plan below fixes them before any final number is produced. Results text
is not written until the experiments are frozen.

### Where the repo currently violates the guide

| Guide item | Current state in this repo | Fix (phase) |
|---|---|---|
| 1.1 Measuring the wrong target | Headline metrics (overlap, suff, margin, sparse) are terms in `ContrastiveObjective`'s own loss, so the evaluation is circular. Lesion overlap measures plausibility, not faithfulness to the model | Primary metrics are interventional and computed on the model, outside the loss (P3) |
| 1.1 Degenerate optimum | The shared mask blanketed 46% of the frame (found late). The shift game's `lambda_sparse=0.05` blankets HAM10000. Brain-tumor budget creeps ×1.19 | Degenerate-optimum audit before full runs (P1) |
| 1.1 Undefined or wrong maths | The objective's overlap term and the allocator's `_disjoint_penalty` are the same quantity, counted twice. "suff" means a raw logit in the contrastive game but a baseline-subtracted logit in the shift game. "Provably reduced overlap" has no proof. CDEA is spelled out three different ways | Equation↔code audit, one name per quantity (P1) |
| 1.1 Theory without proof | "Equilibrium", "best-response dynamics", "game" for what is a single joint loss | Remove, or state exactly as an identical-interest game solved by joint gradient descent (P1) |
| 1.1 Gain without isolating the mechanism | No test that *joint* allocation matters, compared with independent per-class optimisation | Mechanism ablations (P5) |
| 1.2 No held-out test | Medical val is used both for checkpoint selection and for reported numbers. Pets/Dogs evaluate on ~80% training images | Train/val/test for every dataset, with a test lock (P0) |
| 1.2 Hyperparameters chosen on eval data | `lambda_shared_sparse=0.25` was picked on 96 HAM val images, and dogs `lambda_sparse=1.0` was picked after seeing results. The presets have no selection rule | A stated rule, applied on val only (P4) |

| 1.2 One run, small data | Mostly 1 seed, n=105–400 images, ResNet-18 only. Wilcoxon over ≤5 datasets cannot reach p<0.05 | 5 seeds, 8 contrastive and 6 shift datasets, 2 backbones (P2, P4) |
| 1.2 Missing reporting, drift, reproducibility | No git hash, config hash, versions, or platform in result JSON. The repo has a large uncommitted diff. The drafts quote superseded numbers | Provenance in `save_json`, results doc generated by script (P0, P6) |
| 1.3 Baselines | The only baseline is our own `naive_contrastive`. No skeptic baseline (attribution of the logit margin) and no neighbouring family (Extremal Perturbations, CVE). Budgets are not matched | Full baseline set, one scorer, matched area (P2) |

## Execution across sessions

The work is split into **28 stages**, each sized for one agent session (one Cursor chat). The Phase
sections further down are the *specifications*. The stages are the *execution order*.

### Continuity mechanics
- **The plan lives in the repo.** Stage S01 copies this file to `docs/paper/PLAN.md`, the source of truth that every later session reads. It also creates `docs/paper/PROGRESS.md`, which holds:
  - a stage status table (todo / in progress / done / blocked, with commit hash and PR link);
  - a decisions log (date, decision, reason);
  - open issues;
  - running background jobs (command, log path, PID, expected finish);
  - a **"Next session" block**: the stage ID, its first concrete step, and anything the next session must know.
- **Agent rules in the repo** (`AGENTS.md` and `.cursor/rules/paper-workflow.mdc`, see "Running with Cursor agents") point every new chat at `docs/paper/PROGRESS.md`, so it finds the plan without being told.
- **Session start protocol:**
  1. `git pull`
  2. read `PROGRESS.md` and the stage card
  3. `git status` must be clean
  4. run tests
  5. check background jobs listed in `PROGRESS.md`
- **Session end protocol:**
  1. tests pass
  2. small commits pushed (see Version control)
  3. update `PROGRESS.md`, including the next-session block, and push that too
- **If a stage overruns**, stop at a commit boundary, split the stage in `PROGRESS.md` (S12 → S12a/S12b), and record where it stopped. Never leave uncommitted work at the end of a session.
- **Long compute** (training, final grids) runs as resumable background jobs that outlive the session:
  - each cell writes a manifest entry plus a done marker, and a rerun skips completed cells;
  - logs go to `results/paper/logs/`;
  - a later session checks progress and does not babysit it.
- **Independent review stages** (S24, S28) are deliberately done in a *fresh* session that did not write the code or text being checked. Baseline PRs are reviewed and merged by you.

### Running with Cursor agents

The plan works in Cursor as is. These additions replace the parts that relied on Claude Code.

**1. Rules files (written in S01, committed).**
- **`AGENTS.md`** at the repo root, and **`.cursor/rules/paper-workflow.mdc`** with `alwaysApply: true`, holding the same content. It contains:

  - **Hard prohibitions:**
    - never run with `--final` or read the test split before the `eval-plan-frozen` tag;
    - never edit `EVAL_PLAN.md` after it is frozen;
    - never type or edit a result number by hand;
    - never weaken or delete a test to make it pass;
    - never change a baseline's algorithm (B2);
    - never merge your own baseline PR;
    - ask before downloading any dataset or package.
  - **Pointers:** `docs/paper/PLAN.md` for specs, `docs/paper/BASELINES.md` for the dossier, and the guide's Part 1 checklist (copy the guide into `docs/paper/PAPER_LESSONS_AND_WRITING_GUIDE.md`, since `~/Downloads` is outside the repo).

**2. Kickoff prompt** (`docs/paper/KICKOFF_PROMPT.md`), pasted into every new Cursor chat:
> Read AGENTS.md and docs/paper/PROGRESS.md. Run the session start protocol. Do the stage named in the "Next session" block, following its spec in docs/paper/PLAN.md. Commit in small pieces and push each one. Stop at a commit boundary if the stage does not fit. Before ending, run the session end protocol and update the "Next session" block.

**3. Use local Agent mode, not Cursor's cloud Background Agents, for anything that touches data or compute.**
- `data/` and the checkpoints are git-ignored and live only on this machine, and the experiments need MPS. A cloud agent would silently fall back to the random-batch dataset path.
- Background Agents are fine only for pure-code stages that need no data, for example parts of S05, S10, S17 and the S25–S27 writing. Even then their tests must pass locally before merge.

**4. Long jobs must outlive the chat.** Cursor's agent terminal may stop a process when the chat ends or the window closes.
- Launch training and grids with `nohup … > results/paper/logs/<job>.log 2>&1 &`, or inside `tmux`. Record the PID and log path in `PROGRESS.md`.
- Runners must be resumable (done markers per cell), because the machine may sleep. Use `caffeinate -i` around long runs on macOS.

**5. Independence for review stages.** The "fresh session" requirement for S24 and S28 (and baseline PR review) means:
- a new Cursor chat, given only the kickoff prompt plus the review brief, with no history from the authoring chat;
- preferably a different model from the one that wrote the code or text, so the review is not the author checking itself.

**6. Model choice.** Use the strongest available model for:
- S05 (equation audit);
- S10–S14 (baselines);
- S17 (stats);
- S18 (G1 decision);
- S24 and S28 (audits).

Mechanical stages (S01, S07–S09, S20–S22) can use a faster model.

**7. Guard against drift between chats.**
- Every stage's exit check runs as a command whose output is pasted into `PROGRESS.md`, rather than taken on the agent's word: test summary, `git status`, `git log --oneline -5`, and the paths of produced files.
- Decisions made in chat go into the decisions log in the same session, or they are lost.

**Mapping to weeks.** At roughly 2 sessions per week, plus background compute, this matches
the ~15-week timeline below.

## Version control: small commits, pushed as they happen

Every change is a small commit pushed straight away, so that any regression can be found with
`git bisect`, and any result can be traced to the exact code that produced it.

**Branches and tags**
- `main` stays stable. Each phase works on its own branch from `main`: `paper/p0-hygiene`, `paper/p1-formulation`, `paper/p2-baselines`, `paper/p3-eval-plan`, `paper/p4-selection`, `paper/p5-final-runs`, `paper/p6-results`, `paper/p7-writing`.
- Each phase ends with a PR into `main`, merged once tests pass.
- Gates are tagged: `g1-pilot`, `eval-plan-frozen`, `final-runs-v1`, `submission-v1`. Final test-set runs may only start from a tagged, clean commit.

**Commit rules**
1. One logical change per commit, together with its test. For example, "Seed the eval subset in ablation_contrastive" is one commit, and "Hold out the Pets/Dogs complement split" is another.
2. `PYTHONPATH=. python -m pytest tests/` passes before every commit, so every commit is bisectable.
3. Push after every commit (`git push origin <branch>`). Never batch pushes.
4. Code and results never share a commit. A results commit message names the code commit hash that produced it and the command that was run.
5. A commit that changes numbers says so in its message, for example "invalidates Stage 3 ablation; rerun pending".
6. Experiment runners refuse `--final` on a dirty tree. The provenance field records the commit hash, so every JSON points to a pushed commit.

**Step 0: commit the existing uncommitted work in logical pieces, before any new change**

The tree currently has about 30 modified files and a large untracked set. Commit them in this order, on `paper/p0-hygiene`, pushing after each:
1. `.gitignore`: add `*.pt`, `*.mp4`, `.DS_Store`, `results/**/checkpoints/`, `results/**/models/`. Untrack the 5 tracked `.DS_Store` files. Without this step, about 3.7 GB of checkpoints under `results/` and `scripts/out/` would be committed.
2. `base_evidence/` (Grad-CAM changes, `library_adapters.py`, `occlusion_regions.py`).
3. `modality/grid_regions.py` (mask clamp) and `instantiations/contrastive/objective.py` (`lambda_shared_sparse`, `mass_scale`).
4. `core/` (`runner.py`, `reporting.py`, `visualization.py`).
5. Training and eval scripts, one commit per script family: `train_backbone`; `ablation`/`run_experiments`; the `eval_*` scripts; the dataset `prepare_*` scripts.
6. Plotting, deck, and notebook builders.
7. Tests (`tests/test_pass_conditions.py`).
8. Docs (`docs/*.md`, `CLAUDE.md`).
9. Historical results: JSON/CSV/MD only (about 165 MB excluding checkpoints), as one commit labelled as pre-audit results. The deck video and slides move to git LFS or stay out of the repo.

After step 0, `git status` is clean and every later change is a small, separate commit.

**Raw result storage for the new runs.** Store per-image results as `.csv.gz` under
`results/paper/<experiment>/<dataset>/<method>/seed<N>.csv.gz`, plus a JSON summary. Check the
total size after the Phase 0 throughput benchmark. If it goes above ~500 MB, move the per-image
files to git LFS rather than leaving them out, because the statistics must be recomputable from
the raw data.

## Phase 0 — Hygiene and infrastructure (week 1)

1. **Sampling and leakage.** In `scripts/ablation_contrastive.py:_get_eval_loader` and
   `scripts/run_experiments.py`, replace the prefix read with a seeded `randperm` Subset. This
   matches what `scripts/eval_localization.py` already does. Pets/Dogs must hold out the
   complement of `train_backbone.py`'s `random_split(seed=42)`. Add a regression test with a
   class-sorted fake ImageFolder.2. **Three-way split for every dataset**, recorded as index files under `data/splits/<dataset>.json`:
   - HAM10000: keep the current lesion-grouped `val` as **test**, and carve a lesion-grouped **val** from `train`.
   - Brain tumor: keep `Testing` as **test**, and carve a patient-grouped **val** from `Training`.
   - Torchvision datasets: official test set as **test**, 10% of train as **val**.
   - Rule: training uses train. Checkpoint selection and every CDEA/baseline hyperparameter use val. Every reported number uses test.
3. **Test lock.** A shared loader refuses `split="test"` unless `--final` is set *and* the run's config hash appears in the frozen `EVAL_PLAN.md`. This makes it mechanically impossible for test data to enter a decision.
4. **Provenance.** Extend `core/reporting.py:save_json` so every result records git commit, dirty flag, config hash, torch/torchvision versions, platform, device, timestamp, and data-split hash. Final runs refuse a dirty tree (see Version control).
5. **One evaluation library.** `regions_to_pixels`, `mass_in`, `random_translate`/`roll_masks`, `noisy_linear_impute`, `_paired`, and Spearman are currently duplicated across `scripts/eval_*.py`. Consolidate them into `evaluation/` (`masks.py`, `removal.py`, `metrics.py`, `nulls.py`) so that **every method, ours and baselines, is scored by the same code on the same inputs**.
6. Fix the 3 failing tests in `tests/test_interaction.py`: the interaction module is not moved to the input device.
7. **Throughput benchmark** on MPS: forward/backward passes per second for ResNet-50 and ViT-B/16. Use it to set per-dataset `n` so that the full grid fits the compute budget (see Phase 5).

## Phase 1 — Formulation audit and degenerate-optimum checks (week 1–2, val data only)

**Equation↔code table** (`docs/paper/EQUATION_AUDIT.md`): for each paper equation, record the
file and line that implement it. Decisions to make there:
- Merge objective `overlap` and allocator `_disjoint_penalty` into one term with one weight (`instantiations/contrastive/allocator.py`, `instantiations/contrastive/objective.py`).
- Rename quantities: *kept logit* (contrastive) and *baseline-subtracted kept logit* (shift), and use one name per quantity everywhere. Choose a single expansion of CDEA.
- Make `lambda_shared_sparse > 0` the default.
- Give the shift objective a mass target like `lambda_mass`, so that `lambda_sparse` is not the only brake (`instantiations/shift/objective.py`).
- Remove the equilibrium/convergence/provable language. Describe the method as optimisation of a single joint loss. "Game" may stay only as the formal identical-interest game.

**Cheapest way to maximise each objective.** Check each case on 2 dev datasets (CIFAR-10, HAM10000), using val:

| ID | Degenerate route | Check |
|---|---|---|
| D1 | Shared mask blankets the frame | Shared mass, fraction of regions >0.5, evidence capture vs area |
| D2 | Adversarial soft masks (fractional blends that excite logits) | Score soft masks vs masks binarised to the same top-area. A large gap means adversarial |
| D3 | Margin raised by suppressing the foil rather than supporting k | Report z_k and z_l separately, beside the margin |
| D4 | Disjoint but arbitrary cells (overlap → 0 trivially) | Evidence capture ×chance, and a translated-mask null on the primary metric |
| D5 | Budget creep | Mass ratio per dataset. Flag anything above ×1.1 |
| D6 | Shift robust mask blankets the frame, or shortcut mask = complement of robust | Mass, overlap with complement |
| D7 | `id_ood_gap` reported as a method result | It is a property of the model. Move it to the dataset table |

Exit: no route is open, or it is closed by a constraint the paper names.

## Phase 2 — Datasets, models, baselines (week 2–5, in parallel)

### Datasets (unit of analysis = dataset)

**Contrastive game, 8 datasets.** With n=8, the minimum two-sided Wilcoxon p is 0.0078, which
is enough to survive Holm over 3 comparisons.
CIFAR-10, CIFAR-100, Oxford-IIIT Pet (37 breeds), Stanford Dogs, CUB-200, ImageNet-S subset
(pretrained models, segmentations available), HAM10000, brain-tumor MRI. MNIST is kept as a
smoke test only.

**Shift game, 6 datasets** (minimum p = 0.031, so the family can hold only **one** confirmatory
comparison; this is stated in the plan):

| Dataset | Environments | Paired? |
|---|---|---|
| Waterbirds | Bird foreground composited on land vs water backgrounds (CUB masks + Places) | Yes, counterfactual pairs |
| ImageNet-9 Backgrounds | `original` / `mixed_same` / `mixed_rand` | Yes |
| Stanford Dogs | Background restyling (existing `eval_robust_shortcut_dogs.py`) | Yes |
| Planted-patch CIFAR-10 | Patch moved or removed | Yes (synthetic, exact ground truth) |
| ColoredMNIST | Re-coloured | Yes (synthetic) |
| Waterbirds natural groups | Unpaired group-statistics objective variant | No |

The unpaired variant answers the documented weakness that environments are transformations of
one image. It needs a new group-statistics objective (per-group mean kept logit, variance
across group means) in `instantiations/shift/`.

**Backbones.** ResNet-50 is primary. ViT-B/16 is a robustness check at 14×14 and uses IG or
occlusion, because Grad-CAM returns a zero field on ViT. **Seeds:** 5 per configuration. For
datasets we train, a seed means an independently trained checkpoint plus a test-sample draw.
For ImageNet-S (fixed public weights), a seed means a test-sample draw. Allocation itself is
deterministic, so MPS run-to-run variation is measured separately (rerun one configuration
3×) and reported.

**Model table.** Top-1 and balanced accuracy per dataset × seed, selected on val. For shift
datasets, also each model's reliance on the shortcut (ID–OOD gap, worst-group accuracy).

## Baseline protocol

### B1. Every baseline answers a named reviewer question

| Tier | Method | Reviewer question it answers | Reference implementation (pinned) |
|---|---|---|---|
| **Core, contrastive** | Grad-CAM and IG of the **logit margin** z_k − z_l | "Why not just attribute the margin?" (the simplest skeptic) | `pytorch-grad-cam` with a margin target, Captum `IntegratedGradients` with a margin forward function |
| Core | **Extremal Perturbations**, per class *and* a contrastive variant scoring z_k − z_l | "You optimise masks. Fong et al. already do, and at a fixed area." (same method family) | TorchRay `extremal_perturbation`, official (Fong et al.). Its native `areas` parameter is set to a, so the budget matches by construction |
| Core | **Counterfactual Visual Explanations** (Goyal et al. 2019) | "Goyal et al. already answer 'why k not l' on fine-grained data." (closest prior art) | No official code is assumed. Reimplement, then validate against the paper (B3) |
| Core | Base evidence (Grad-CAM, IG) | "Does allocation add anything over its own input?" | Our providers, cross-checked against the libraries (B4) |
| Core | Random area-a mask | "Is the metric trivially satisfied?" (weak floor) | `evaluation/nulls.py` |
| Extended | Contrastive Grad-CAM (Prabhushankar et al. 2020) | "Gradient-based contrastive saliency exists." | Reimplement (it is a one-line change to Grad-CAM's target). Validate on the authors' qualitative examples |
| Extended | **SCOUT** (Wang & Vasconcelos, CVPR 2020) | "Discriminant 'why A not B' explanations exist." | Official code if it is public and runs. If not, related work states the attempt and the reason |
| Extended | RISE, per class and margin variant | "Sampling-based perturbation would do the same." | Official RISE code, with seeded mask generation |
| Extended | `naive_contrastive` | Our own earlier floor | Ours. Shown as a sanity row only |
| **Core, shift** | Attribution difference \|E(x_id) − E(x_ood)\| (shortcut), min over environments (robust) | "Why not just diff two heatmaps?" | Same providers as above |
| Core | **SpRAy** (Lapuschkin et al. 2019, "Unmasking Clever Hans") | "Explanation-based shortcut discovery already exists." (closest prior art for the shift game) | Official CoRelAy + Zennit (Fraunhofer HHI). The cluster-level shortcut is converted to a per-image map via the cluster's mean relevance (B6) |
| Core | Per-environment Extremal Perturbations, differenced | Same method family | TorchRay |
| Core | Base evidence, random area-a mask | Floors | As above |
| Exploratory | DFR, GroupDRO | Downstream worst-group accuracy as a reference point only. These are training methods, not explanations, and the text says so | Official code |

- **CEM** is not run. Related work explains why: it gives pixel-level pertinent negatives with an autoencoder and was demonstrated at MNIST scale, not region evidence. The guide's rule is that every cited method is either compared or the reason for not comparing is engaged in the text.
- The Extended tier runs on all datasets if Phase 0 compute allows. Otherwise it runs on a stated, matched random subsample, never silently dropped.

### B2. Pinned, unmodified reference code
- Third-party code is vendored under `third_party/<name>@<commit>`, with its licence. Library versions are pinned in `requirements.txt`.
- Any patch needed to run on our stack (for example, TorchRay on current PyTorch/MPS) is its own commit, with a one-line reason, listed in the dossier. Patches may change only API or device, never the algorithm.
- Each method's authors' recommended defaults are recorded.

### B3. Reproduce a published number for every baseline
Each baseline reproduces one number from its own paper, in its own setting, within a stated
tolerance. That number goes into an appendix table. Reproductions run in parallel with the pilot
and selection. They gate entry to a comparison only for CVE in family C (B8).

| Baseline | Reproduction target |
|---|---|
| Extremal Perturbations, Grad-CAM | TorchRay's own pointing-game benchmark on a PASCAL VOC subset, against the numbers TorchRay publishes |
| RISE | Deletion/insertion on an ImageNet-val subset with ResNet-50, against Petsiuk et al. 2018 |
| CVE | The paper's CUB keypoint/edit-count result, on the paper's backbone if available. If the paper does not specify enough to reproduce, that is recorded and the closest checkable quantity is used |
| SCOUT, SpRAy | One result from each paper's own experiments |
| Margin attribution, contrastive Grad-CAM | Toy-model unit tests with a known answer (B5), because there is no single published number |

If a reproduction misses its tolerance, the baseline is debugged before the freeze. If it still misses at the freeze, the appendix states the gap and the main table marks that baseline's row.

### B4. Identical inputs for every method
- **One model wrapper.** The model takes raw [0,1] input, and ImageNet normalisation is a layer *inside* the model. Every method, ours and theirs, calls the same wrapped model. This prevents a repeat of the normalisation bug, and library baselines that expect normalised input get it automatically. An assertion checks the input range at the wrapper.
- **The same hypotheses.** The model's top-K classes and the same foil l (rank-1) are passed to every method. No method picks its own classes.
- **The same images, splits, and preprocessing**, read from the same loader.
- **Cross-implementation check.** Our Grad-CAM and IG providers are checked against `pytorch-grad-cam` and Captum on 100 val images. The Spearman correlation must be ≥0.95 before either is used. This validates our base evidence as a baseline in its own right.

### B5. Matched output and budget, checked in both directions
- Every method outputs a per-hypothesis map. That map goes through **one** conversion in `evaluation/masks.py`: upsample to pixels (bilinear, the same for all), take the top-a% of pixels, with seeded tie-breaking.
- **Method-specific conversions** are documented and unit-tested:
  - CVE edits: cells ranked in edit order.
  - SpRAy: the cluster relevance map.
  - Extremal Perturbations: its native mask at area a.
- **Resolution fairness.** Pixel-resolution baselines (IG, Extremal Perturbations, RISE) are scored twice: at native resolution, and pooled to CDEA's grid. This shows whether any gap comes from the method or from resolution. Both results are reported.
- **Compute fairness.** Extremal Perturbations and RISE are reported at their authors' defaults *and* at the same number of forward passes as CDEA (T × K). CDEA at T ∈ {10, 25, 50, 100} gives the cost–quality curve.
- **Tuning fairness.** Every method gets the same val tuning budget: the same number of configurations, selected by the same rule on the same val metric. Both rows go in the appendix: authors' default, and val-tuned. The main table uses val-tuned for every method, including CDEA.

### B6. Audit the baseline pipeline as hard as our own
- **Toy model with a known answer.** A synthetic image whose class-k evidence sits in known regions, and a small model trained to use it. Every method must recover those regions. Run in CI.
- **Edge cases:**
  - empty or constant maps;
  - NaN;
  - ties at the top-a threshold;
  - all-negative attributions (clamp policy stated);
  - K smaller than requested.
- **Symmetry test.** CDEA's masks are passed through the exact baseline adapter path, and must score identically to the direct path.
- **Randomness.** RISE masks, GradientShap, and SpRAy clustering are seeded. Run-to-run variance is measured on 3 repeats and reported.
- **Failures** (NaN, timeout, empty output) are counted per method and per dataset and reported as a success rate. A failed image is scored as the random-floor value, a rule fixed in advance, and never dropped.
- **Second pair of eyes.** Each baseline lands as its own PR on `paper/p2-baselines`, with a review checklist (B2–B6). You review and merge it. Nobody merges their own baseline.

### B7. Reporting rules
- A baseline that beats CDEA on any metric or dataset stays in the table, and the text says plainly where each method is better. `FRAMING.md` commits to this before results exist.
- No self-reported scores. Every number comes from `evaluation/` on the shared inputs.
- The dossier `docs/paper/BASELINES.md` holds one entry per method:
  - citation and reviewer question;
  - source and commit;
  - patches;
  - defaults and tuned settings;
  - reproduction result;
  - conversion rule;
  - known failure modes;
  - cost.

  The appendix's baseline section is generated from it.

### B8. Gate G0 (baselines may enter a comparison)
G0 is an entry check. A Core baseline enters a comparison when it has pinned authors' code or a
reimplementation that names its algorithm, passing cross-checks and toy tests (B4, B6), a merged
reviewed PR, and a dossier entry. Tag `g0-baselines`. The B3 reproductions run in parallel and are
reported in the appendix. They do not hold up the G1 pilot, selection, or writing. CVE is the
exception: it is our reimplementation, so its CUB reproduction must be recorded before the freeze
for CVE to stay in family C. Otherwise family C is the other two comparisons under Holm over 2,
and CVE is an exploratory row. Details and status: `docs/paper/G0.md` (user decision 2026-10-07).

## Phase 3 — Evaluation design, frozen as `docs/paper/EVAL_PLAN.md` (week 4–5)

### Matched budget (guide 1.3)

Every method's per-hypothesis map is converted to a **binary pixel mask covering a fixed
fraction a of the image** (top-a by map value; ties broken by a seeded jitter). Scoring happens
in pixel space, which removes both differences in mass and differences in grid. The primary
budget is a = 5%. Robustness checks use a ∈ {2.5%, 10%}. Soft-mask scores are reported only as
the D2 check.

### Removal operator

Optimisation uses the blur `keep`. The primary evaluation uses **ROAD noisy-linear imputation**
(`noisy_linear_impute`), a *different* operator, so that the method is not scored on the
perturbation it was fitted to. The blur operator is reported beside it to show that the
difference does not drive the result (guide 1.1).

### Metrics: what each compares against, and which Co-12 property it measures

| Metric | Question | Compared against | Property | Status |
|---|---|---|---|---|
| **Contrastive deletion score CD@a** = m(x∖M_l) − m(x∖M_k), where m = z_k − z_l, k = rank-0 class, l = rank-1 class | Does removing k's evidence lower k-over-l, and removing l's evidence raise it? | The model's own logits | Contrastivity, correctness | **Primary (contrastive)** |
| Full K×K deletion matrix: diagonal − off-diagonal, and the \|diag\|/off ratio | Is unique evidence class-specific across all hypotheses? | Model | Contrastivity | Secondary |
| Deletion / insertion AUC, ROAD MoRF/LeRF | Is the evidence for k faithful? | Model | Correctness | Secondary |
| Model-randomisation Spearman ρ (Adebayo et al.) | Does the explanation depend on the model? | Same method on a randomised model | Correctness | Secondary, pass/fail filter for every method |
| Planted two-patch recovery: patch A in class k, patch B in class l; mass of M_k on A, M_l on B | Does each side's mask find its own class-unique cue? | Exact planted ground truth | Correctness (controlled) | Secondary, on CIFAR-10, Pet-37, CUB |
| Mask area, connected components | How compact is the explanation? | — | Compactness | Descriptive |
| Seed/perturbation stability (Spearman between runs, and under small input noise) | Is it stable? | Itself | Continuity, consistency | Descriptive |
| Lesion/part/segmentation overlap with the null family (uniform, centre, translated) | Plausibility | Human annotation | Coherence | **Exploratory only**. The centre-prior result is reported as a negative finding |
| **Shift: environment-disagreement reduction** ΔD = D(x) − D(x with M_sho removed in all envs), minus the same for random at equal area, where D = \|p_y(x_id) − p_y(x_ood)\| | Does the shortcut mask capture what makes the model change across environments? | Model | Correctness | **Primary (shift)** |
| Shift: robust-mask kept-logit stability across environments | Is the robust evidence environment-invariant? | Model | Correctness, consistency | Secondary |
| Shift: M_rob mass on foreground, M_sho on background | Do the masks match the known shortcut structure? | Dataset construction (segmentation) | Correctness (controlled) | Secondary |
| Shift: worst-group accuracy after test-time masking of M_sho | Is the shortcut map useful downstream? | Labels (stated as a different target) | Use case | Exploratory. DFR/GroupDRO are shown as reference points, not as like-for-like comparisons |
| Cost: forward+backward passes per explanation, plus wall-clock on MPS | What does it cost? | — | — | Descriptive. Training and checkpoint costs excluded, and this is stated |

Support is reported for every number: n images, the fraction with valid K, and the fraction
flagged as degenerate (mass < ε, or mass above the budget).

### Statistical protocol (guide 1.5)

- Unit = dataset. Average over 5 seeds within each dataset, then compare methods across datasets.
- **Confirmatory family C (contrastive)**, metric CD@5% under ROAD, 8 datasets, two-sided Wilcoxon signed-rank with Holm correction:
  CDEA vs margin attribution (the skeptic baseline), CDEA vs contrastive Extremal Perturbations (same family), CDEA vs CVE (closest prior art).
  CDEA vs base evidence appears in the main table as a secondary comparison. It is left out of the family because Wilcoxon with n=8 cannot carry 4 comparisons under Holm unless nearly every dataset wins (the 4th threshold needs p ≤ 0.0125, and 7 of 8 wins gives p = 0.0156).
- **Confirmatory family S (shift)**, metric ΔD, 6 datasets: CDEA-shift vs the strongest baseline on val. Only one comparison, because of the power limit.
- Report wins out of N, mean difference, one bootstrap 95% CI over datasets, and the Holm-adjusted p. Everything else is labelled exploratory. Per-image paired tests are descriptive only.
- Robustness checks on each confirmatory claim:
  - leave one dataset out;
  - exclude the 2 dev datasets;
  - second backbone;
  - blur operator;
  - a ∈ {2.5%, 10%};
  - effect size compared with the measured MPS run-to-run variation.

  A claim is called robust only if it survives all of them.
- All statistics are computed from raw per-image/per-run files by `analysis/stats.py`, which is committed to the repo.

### Claims to make and not make (`docs/paper/FRAMING.md`)

Each claim is tied to a table and a test. The current draft list:
- **Make, if confirmed:**
  - CDEA's unique evidence is more contrastive than margin attribution and Extremal Perturbations at matched area (family C).
  - Allocation makes explanations more model-dependent (sanity checks).
  - The shortcut mask captures cross-environment disagreement (family S).
  - Lesion overlap cannot validate contrastive explanations (centre-prior finding).
- **Do not make:**
  - Good localisation.
  - Same budget (true on only one dataset).
  - Equilibrium or convergence properties.
  - Scalability beyond what was measured.
  - Usefulness to people (no study).

**Decision gate G1 (framing).** Pilot family C on val of the 2 dev datasets. G1 decides the
headline claim, not whether writing starts. If CDEA is not ahead of margin attribution on both
dev datasets, decide with the user between running the selection candidates and reading again,
or reframing as the evaluation paper. Seeds 2–4 training and the freeze wait for that decision.
The read-out rule is in `docs/paper/G1.md`.

## Phase 4 — Hyperparameter selection on val (week 5–6)

- One global CDEA configuration (λ's, steps, lr, `lambda_shared_sparse`, IG baseline), selected on val of the 2 dev datasets by a stated rule: maximise CD@5% on val, subject to D1–D5 passing.
- The IG baseline is chosen by the sanity check on val. Zero baseline failed on MRI, so blur is expected.
- The same rule and budget apply to each baseline's own parameters.
- The main result is reported on all 8 datasets *and* on the 6 non-dev datasets (guide 1.2, choices made on a subset of runs).
- `EVAL_PLAN.md` is then frozen: config hashes, test sample seeds, families, metrics. Freezing it unlocks test.

## Phase 5 — Final runs on test (week 6–9)

Grid:

| Game | Datasets | Seeds | Backbones | Methods |
|---|---|---|---|---|
| Contrastive | 8 | 5 | primary (+ViT check) | ~7 |
| Shift | 6 | 5 | primary (+ViT check) | ~5 |

**Mechanism ablations** go in one table. Each row removes one component, with the primary metric and its components:
- A1 independent per-hypothesis optimisation (no overlap term, no margin term, K separate runs). This isolates *joint* allocation, the method's central mechanism.
- A2 no margin term.
- A3 no overlap term.
- A4 no shared mask.

- Shift: paired vs unpaired objective, and with vs without the mass target.

Report what each ablation can and cannot separate (confounds: forward passes, number of masks, K).

## Phase 6 — Results document by script (week 9–10)

- `analysis/build_results.py` reads the raw per-run files and writes `results/paper/RESULTS.md` and LaTeX tables (the existing `scripts/build_results_notebook.py` is the pattern).
- The output contains: the main table, the per-dataset table, the family tables (wins, Δ, CI, p_Holm), robustness checks, ablations, cost, and the model table.
- Automatic assertions:
  - masks within [0,1];
  - areas equal to a ± tolerance;
  - probabilities within [0,1];
  - no NaN;
  - n matches the plan.
- Read a sample of output masks by eye for every dataset before any writing starts.
- An independent audit of every number in the draft against `RESULTS.md`, by someone who did not write the text.

## Phase 7 — Writing (week 10–13), in the guide's order

1. Problem formulation (shared objects: units, keep/remove, hypotheses, budget).
2. Method. Contrastive and shift each get one numbered equation block, with every term's weight and the degenerate solution it rules out.
3. Setup.
4. Results.
5. Ablations.
6. Discussion and limitations (two paragraphs).
7. Related work. Groups:
   - per-class attribution;
   - perturbation mask optimisation (Fong & Vedaldi, Extremal Perturbations, RISE);
   - contrastive explanation (Miller 2019, Lipton; contrastive Grad-CAM, SCOUT, CVE, CEM);
   - shortcut/spurious-feature discovery;
   - explanation evaluation (Adebayo, ROAD, Nauta et al. Co-12).

   It ends with a positioning paragraph naming the three closest methods for each novelty claim.
8. Introduction.
9. Abstract (with the main negative result).
10. Conclusion.

Then a hostile review against Part 1 of the guide, a style pass against §2.1 (no colons or semicolons in prose, no revision language, no filler words), and a compile pass. The paper source lives in `paper/`, and old drafts (`docs/GAMBIT_PAPER.md`, `docs/CDEA_CONTRASTIVE_PAPER.md`) are not edited.
